Classification legend:
- `Allowed`: Search hit is ID-backed construction/traversal/test code or non-semantic display/source/backend metadata.
- `Suspicious`: Search hit may be safe, but needs a focused proof or nearby test.
- `Disallowed`: Search hit can affect semantic identity by name/string/raw ID and must be fixed before completion.
- `Fixed`: Search hit was disallowed or suspicious, then removed or guarded by implementation in this task.

## Soundness Questions

1. Could two same-named types from different modules/crates compare equal?
2. Could two same-named generic parameters from different owners compare equal or substitute into each other?
3. Could two same-named traits or associated types collide in a projection?
4. Could lowering, mono, or codegen select a trait impl by display name after an ID-backed target exists?
5. Could artifact loading accept a forged or stale type/projection/generic owner ID?
6. Could export/import/display names overwrite or shadow distinct semantic IDs?
7. Could backend symbol construction feed back into semantic equality or dispatch?

## Soundness Synthesis

1. Same-named nominal types cannot compare equal after lowering because `Type::Struct { id, args }` and `Type::Enum { id, args }` carry the declaration `DefId` as semantic identity. Audited boundaries include `lower_parse_type_inner_with_slice_context` in `lib/src/lower/types.rs`, nominal matching in `infer_generic_subst_from_types` in `lib/src/lower/types_helpers/helpers.rs`, nominal remapping in `Type::remap_def_ids` in `lib/src/types/mod.rs`, and layout/codegen lookup in `llvm_type` in `lib/src/codegen/types.rs`, all of which preserve or compare the `DefId` rather than a display name. Focused evidence: `cargo test -p rock-lib same_named_nominal_types_are_distinct_by_def_id -- --nocapture`, plus the stale-identity search row for `lib/src/types/mod.rs` classifies the remaining nominal hits as ID-backed construction/traversal/tests.
2. Same-named generic parameters cannot collide because semantic generic identity is `Type::Generic(GenericParamId { owner, index })`, not the parameter display string. Audited substitution and bounds paths include `generic_substitution_for_owner` and `current_generic_type_for_name` in `lib/src/lower/mod.rs`, `build_function_header` and `remap_generic_owner_in_type` in `lib/src/collect/headers.rs`, `substitute_type_with_map` in `lib/src/mono/substitute.rs`, and `generalize_single_function` in `lib/src/infer/generalize.rs`; bounds are stored as `HashMap<GenericParamId, Vec<TraitBound>>`. Focused evidence: `cargo test -p rock-lib generic_param_identity_is_owner_and_index -- --nocapture`, `cargo test -p rock-lib generic_params_with_same_name_are_distinct_by_owner -- --nocapture`, and `cargo test -p rock-lib substitute_generics_uses_generic_param_identity -- --nocapture`.
3. Same-named traits and associated types cannot collide in projections because `Type::Projection` carries `trait_id: DefId`, `assoc_type: AssociatedTypeKey`, `trait_args`, and a base type; the associated-type key includes the declaring trait owner and associated type ID. Audited projection paths include `lower_parse_type_inner_with_slice_context` in `lib/src/lower/types.rs`, conformance projection substitution in `lib/src/lower/traits/conformance.rs`, `resolve_projection_type` in `lib/src/codegen/types.rs`, and artifact projection validation in `ProductNominalTypeValidator::validate_projection` in `lib/src/crate_artifact/load.rs`. Focused evidence: `cargo test -p rock-lib projection_identity_uses_trait_and_assoc_type_ids -- --nocapture`, `cargo test -p rock-lib conformance_does_not_substitute_projection_with_different_trait_args -- --nocapture`, `cargo test -p rock-lib product_artifact_rejects_projection_assoc_owner_mismatch_across_crates -- --nocapture`, and `cargo test -p rock-lib product_artifact_remaps_projection_type_ids -- --nocapture`.
4. Lowering, mono, and codegen cannot select trait impls by display name after IDs exist because semantic selection is driven by selected targets, receiver IDs, trait IDs, trait args, method IDs, or instance origins. Audited lowering paths include `find_matching_trait_impl_by_id` use in `lib/src/lower/expression.rs` and ID-backed `HirMethodCallTarget` construction in `lib/src/lower/control_flow/secondary.rs`; audited mono paths include `monomorphize_method_call` and `monomorphize_static_impl_method_call` in `lib/src/mono/methods.rs`, plus `InstanceOrigin::ImplMethod { owner, method }`; audited codegen paths include `register_trait_impls`, `find_trait_impl`, and method-call dispatch in `lib/src/codegen/mod.rs` and `lib/src/codegen/expr/mod.rs`. Remaining fallbacks are guarded: unqualified enum variant display lookup in `lib/src/lower/control_flow/pattern.rs` runs only for unresolved `Type::TypeVar`/targetless contexts, static generic impl targetless fallback in `lib/src/mono/methods.rs` now refuses specialization instead of scanning by name, codegen targetless direct/builtin array fallbacks are backend-only after no selected trait target exists, and `resolve_projection_type`'s array-index fallback is gated by `builtin_index_trait_ids` from selected HIR index targets. Focused evidence: `cargo test -p rock-lib --test integration test_same_name_trait_methods_do_not_dispatch_by_method_name_only -- --exact --nocapture`, `cargo test -p rock-lib static_impl_method_call_without_selected_target_does_not_select_by_name -- --nocapture`, `cargo test -p rock-lib --test integration test_unqualified_same_named_enum_variant_pattern_uses_scrutinee_owner -- --exact --nocapture`, and `cargo test -p rock-lib --test integration test_index_operator_prefers_selected_user_impl_over_builtin_array_index -- --exact --nocapture`.
5. Artifact loading cannot accept forged or stale IDs because serialized ID-bearing fields are validated and remapped before downstream use. Audited functions in `lib/src/crate_artifact/load.rs` include `remap_type_def_ids`, `ProductNominalTypeValidator::validate_projection`, `ProductNominalTypeValidator::validate_method_target`, `remap_generic_bounds`, `remap_function_child_locations`, `remap_trait_ids`, `remap_expr_child_locations`, `remap_impl_ids`, `product_def_id_to_existing_def_id`, and `product_id_has_canonical_binding`; product link metadata is also guarded by `remap_link_data`, `backend_symbols_from_link`, and `unambiguous_product_id` in `lib/src/products.rs`. Focused evidence: `cargo test -p rock-lib product_artifact_rejects_unknown_projection_trait_id -- --nocapture`, `cargo test -p rock-lib product_artifact_rejects_unknown_projection_assoc_type_id -- --nocapture`, `cargo test -p rock-lib product_artifact_rejects_unknown_dependency_projection_trait_id -- --nocapture`, and `cargo test -p rock-lib compiler_products_drop_backend_symbols_for_ambiguous_link_ids -- --nocapture`.
6. Export, import, and display names cannot overwrite semantic IDs because product identity is keyed by `ProductDefId` and display names stay separate from canonical/export identity. Audited functions in `lib/src/products.rs` include `record_display_name`, which records non-semantic display metadata by ID, `record_export_name`, which drops an export into `ambiguous_export_names` on collision instead of overwriting a distinct ID, `PreferredTraitDefaultMethods::{new,get}`, which chooses exact `DefId` trait default bodies, and `unambiguous_product_id`, which drops ambiguous remaps. Focused evidence: `cargo test -p rock-lib compiler_products_drop_ambiguous_export_name_collisions -- --nocapture`, `cargo test -p rock-lib compiler_products_keep_export_name_ambiguous_after_third_collision -- --nocapture`, `cargo test -p rock-lib compiler_products_do_not_export_colliding_impl_method_display_names -- --nocapture`, and `cargo test -p rock-lib compiler_products_prefer_exact_trait_default_method_identity -- --nocapture`.
7. Backend symbols cannot feed back into semantic equality or dispatch because backend names are produced after semantic selection has already chosen HIR/mono identities. Audited mono paths include `InstanceKey`/`InstanceOrigin` construction in `lib/src/mono/registry.rs`, selected method handling in `lib/src/mono/methods.rs`, and external artifact instance registration in `lib/src/mono/external.rs`; audited codegen paths include `register_instances`, `impl_method_backend_symbols`, `register_trait_impls`, and method-call dispatch in `lib/src/codegen/mod.rs` and `lib/src/codegen/expr/mod.rs`, where exact `(impl_id, method_id)` or selected `trait_id`/`trait_args` matches are required before a backend symbol is used. Focused evidence: `cargo test -p rock test_artifact_consumer_calls_dependency_qualified_impl_owner -- --nocapture`, `cargo test -p rock-lib --test integration test_same_name_generic_trait_default_methods_select_bound_trait_body -- --exact --nocapture`, and `cargo test -p rock-lib compiler_products_remap_backend_symbols_to_unambiguous_fallback_ids -- --nocapture`.
